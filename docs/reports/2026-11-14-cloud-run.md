## 3. flag γ แบบไม่มี v (`AMTP_GAMMA_V`)

- ค่าเริ่มต้น (ตาม paper): γ = H(PID ‖ v ‖ H(Enc(L)))
- `AMTP_GAMMA_V=0` หรือ `--gamma-no-v`: γ = H(PID ‖ H(Enc(L)))
- ผลต่อ update: เมื่อ partition เปลี่ยน version ไม่ต้องคำนวณ γ ใหม่ทุก keyword ใน partition นั้น refresh แค่ใบ partition A_j
- ความปลอดภัย: ผู้ใช้ยังตรวจครบ 7 ข้อ (ctx, anchor, idx, papc, part, comp, ct)
  - completeness มาจาก ρ, R^post และ IMT เหมือนเดิม
  - freshness มาจาก Root Anchor (e*, R_D* ล่าสุด) + สาย hash R_D = H(i ‖ e ‖ R^part ‖ R^idx); v ยังอยู่ใน A_j = H(PID ‖ v ‖ R_P)
  - test `amtp_code/tests/test_gamma_flag.py` ยืนยันว่าทุกการโจมตีถูกจับในโหมดไม่มี v (stale ถูกจับที่ anchor, replay ที่ ctx)
- **ต้องให้อาจารย์อนุมัติก่อนใช้ใน paper** เพราะเปลี่ยนสูตร γ ที่ผู้ใช้คำนวณตอน accept และต้องแก้บทพิสูจน์
- ทุก manifest บันทึก `amtp_gamma_v`; `scripts/merge_runs.py` ไม่ยอมรวมผลที่ค่าไม่ตรงกัน

### ทำไม split/merge แบบมี v ช้า

Static-MT ไม่ split partition จึงบวมขึ้นเรื่อยๆ (ใหญ่สุด 259 ไฟล์ตอน θ=64 ขณะที่ AMTP คุมไว้ที่ 64) เมื่อ γ มี v ทุกครั้งที่ partition เปลี่ยน version ต้องคำนวณ γ ใหม่ทุก keyword ใน partition (ประมาณ 1.5 ล้านชิ้นต่อ batch) เวลาต่อ batch จึงเพิ่ม ~6.5 วินาทีทุก 100 batch calibration 100 batch ไม่เห็นการบวมนี้ เวลาที่ประเมินไว้ตอนแรกจึงคลาด

## 7. สิ่งที่เห็นจากผล (ยังไม่ครบ)

- AMTP เป็น scheme เดียวที่จับการโจมตีได้ครบทั้ง 4 แบบ
- ขนาด proof ตอนผลลัพธ์เยอะ: AMTP เล็กกว่า SE-COLLAB และ Du ชัดเจน
- ex5: เวลา query ของ AMTP ต่ำกว่า SE-COLLAB และคงที่เมื่อ domain เพิ่ม
- ex4 (ไม่มี v): AMTP คุม partition ไม่ให้เกิน θ ได้ แต่ต้นทุน update / query ยังสูงกว่า Global-MT
- search / verify ของ AMTP ช้ากว่า baseline ในหลายจุด และ update แบบมี v ช้ากว่าแบบไม่มี v 5.5–7.4 เท่า (b ≤ 100)

## 8. ปัญหาที่รู้แล้ว / งานต่อ

1. เวลา search ของ AMTP โตตาม pQ เพราะ server เปิด posting เต็มของทุก keyword (`amtp_code/amtp/server.py`) — ทางแก้ที่เป็นไปได้: AND pruning, accumulator
2. Validator แบบมี v ที่ b=1000 ใช้เวลาโตเกินเชิงเส้น (597 s เทียบ 7.6 s ที่ b=100) — ยังไม่ได้ profile
3. γ แบบไม่มี v รออาจารย์อนุมัติ + แก้บทพิสูจน์
4. ck / AAD ยังเป็น JSON (หัวข้อ 2)
5. รอ split/merge แบบมี v (w1, w2, w10) และ ex1–ex2 แบบไม่มี v (w3, w5, w6) แล้วรวมผล + ทำกราฟใหม่
